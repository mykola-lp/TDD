# Test-Driven Development

A collection of exercises from the [University of Helsinki TDD MOOC](https://tdd.mooc.fi/), focused on test-driven development, refactoring, and software design.

Each exercise is kept in a separate project directory. See its README for setup and usage instructions.

> **Note:** Each exercise is developed in a separate pull request (PR) to make the changes easier to review and showcase the development process.

## Exercises

### 1. [Small, Safe Steps](./tdd-mooc-small-steps/) · [MOOC exercise](https://tdd.mooc.fi/exercises/#exercise-1-small-safe-steps)

Practice safe, incremental refactoring by replacing `Date` with `Temporal.PlainDate`. Keep tests passing after every small change.

### 2. [Tetris](./tdd-mooc-tetris/) · [MOOC exercise](https://tdd.mooc.fi/exercises/#exercise-2-tetris)

Build a Tetris game using TDD across ten levels. Practice writing tests first, implementing features incrementally, and evolving the design.

### 3. [Untestable Code](./tdd-mooc-untestable-code/) · [MOOC exercise](https://tdd.mooc.fi/exercises/#exercise-3-untestable-code)

Explore code that is difficult to test because of dependencies on time, randomness, files, and global state. Refactor it into testable code and add tests.

### 4. [Legacy Code](./tdd-mooc-legacy-code/) · [MOOC exercise](https://tdd.mooc.fi/exercises/#exercise-4-legacy-code)

Work with the Gilded Rose legacy code: add tests, achieve full mutation coverage, refactor the implementation, and introduce the Conjured items feature.

### 5. [Full-Stack Web App](./tdd-mooc-webapp/) · [MOOC exercise](https://tdd.mooc.fi/exercises/#exercise-5-full-stack-web-app) *(Optional)*

Starter template for a To-Do application with a SPA frontend, API backend, and database. The exercise focuses on a walking skeleton and testing across application layers.

### 6. [Conway's Game of Life](./tdd-mooc-new-js-project/) · [MOOC exercise](https://tdd.mooc.fi/exercises/#exercise-6-conways-game-of-life)

Implement a command-line Game of Life simulator using TDD. It reads an RLE pattern and generation count, then outputs the resulting pattern in RLE format.
